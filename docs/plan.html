배경과 목표 범위 아키텍처 기능 명세 핵심 흐름 데이터 모델 로드맵 리스크 결정 사항

문서 개발 계획서 v0.3작성일 2026-10-13상태 Phase 2 구현 완료 (v0.2.0)

프롬프트 하나로 워크트리부터 PR까지 가는 로컬 개발 도구

지금 터미널에서 손으로 이어 붙이는 작업, 즉 워크트리 생성, 포트를 나눠 서버 띄우기, 화면 확인, PR 작성을 한 화면에서 처리하는 도구를 만든다.

배경과 목표

현재는 Claude Code를 터미널에서 실행하고, 작업마다 워크트리 경로와 포트(예: 3423, 3424)를 머릿속으로 관리한다. 서버가 여러 개 떠 있으면 어느 브랜치가 어느 포트인지 헷갈리고, 같은 테스트 계정으로 두 곳에 로그인하면 세션이 끊기는 문제도 생긴다. PR 본문은 매번 템플릿을 보며 직접 채운다.

목표

  • 티켓 하나당 세션 하나: 세션을 만들면 워크트리, 브랜치, 포트, 환경값이 함께 묶인다.
  • 프롬프트 입력부터 화면 확인까지 창을 바꾸지 않는다.
  • PR은 템플릿에 맞춰 초안이 자동으로 만들어지고, 사람은 검토만 한다.

성공 기준

  • 새 티켓 시작부터 로컬에서 화면을 보기까지 1분 안에 끝난다.
  • 동시에 3개 이상의 워크트리 서버가 포트 충돌 없이 돈다.
  • PR 템플릿 항목이 빠짐없이 채워진 초안이 나온다.

범위

이번에 만드는 것

  • 로컬 Claude Code 세션 연동 (Agent SDK)
  • GitHub 연동 (gh CLI)
  • 로컬 클론 폴더 기준 프로젝트 등록과 BE/FE/통합 자동 감지
  • 프롬프트 입력창과 대화 스트림
  • 기준 브랜치 선택 후 워크트리 생성
  • 프로필별 환경값 관리(AI 분석 후 수정·추가), 빈 포트로 서버 실행
  • FE 미리보기, BE 로그 뷰어
  • 템플릿 기반 PR 생성
  • 테스트 계정 풀 관리

이번에 안 만드는 것

  • 원격 서버 배포, 클라우드 호스팅
  • 팀 단위 멀티 유저, 권한 관리
  • 코드 에디터 기능 (IDE를 대체하지 않음)
  • CI 결과 연동, 리뷰 코멘트 자동 대응
  • DB 마이그레이션 자동 실행

아키텍처

로컬 프로세스를 직접 다뤄야 하므로 Node.js(TypeScript) 오케스트레이터가 중심에 있고, 브라우저 UI는 WebSocket으로 상태를 받는다. localhost 웹앱으로 만든다. 도구를 끌 때 띄워 둔 서버는 오케스트레이터의 종료 훅에서 함께 정리한다.

기술 스택

영역선택이유
UIReact + Vite, Tailwind스트리밍 메시지와 탭 UI를 빠르게 만들 수 있다.
서버Node.js + Fastify, wsAgent SDK가 TypeScript 기준이고 child_process 제어가 쉽다.
Claude@anthropic-ai/claude-agent-sdk터미널 출력 파싱 없이 메시지 타입별로 스트림을 받는다.
Git / GitHubgit CLI, gh CLI사용자의 기존 인증을 그대로 쓴다. 토큰 저장이 필요 없다.
저장소SQLite (better-sqlite3)로컬 단일 사용자에 충분하고 백업이 파일 하나다.
포트get-port사용 중이지 않은 포트를 안전하게 찾는다.

기능 명세

기능동작구현 메모단계
1. Claude 연동세션마다 워크트리를 작업 디렉터리로 하는 Claude Code 세션을 연다. 대화는 이어서 진행된다.query()에 cwd=워크트리, resume=세션 ID. CLAUDE.md 적용을 위해 settingSources: ['project']와 claude_code 프리셋을 쓴다. cwd가 바뀌면 resume이 실패하므로 경로를 함께 저장. 권한은 auto 모드로 실행해 확인 없이 진행한다.MVP
2. GitHub 연동푸시와 PR 생성에만 쓴다. 프로젝트 목록은 GitHub가 아니라 로컬 폴더 기준이다.gh auth status로 로그인 확인. 미로그인 시 안내만 하고 직접 로그인은 하지 않는다.2단계
3. 프로젝트 연동로컬에 클론해 둔 폴더를 등록한다. 현재 브랜치, 워크트리, 원격 주소는 폴더의 git 정보에서 읽는다. BE와 FE를 하나의 워크스페이스로 묶을 수 있다.vite/next → FE, build.gradle/pom.xml → BE, 둘 다 또는 docker-compose → 통합. 감지 결과는 사용자가 수정 가능. git 저장소가 아닌 폴더는 거부.MVP
4. 프롬프트 창대화 스트림과 하단 입력창. 세션별 탭. 이미지 첨부(클립 버튼, 끌어다 놓기, 붙여넣기)와 미리보기 화면 캡처 첨부.텍스트는 마크다운, tool_use는 접힘 카드로. 실행 중 중단 버튼, 소요 시간과 비용 표시. 이미지는 base64로 바꿔 streaming input 메시지의 content 블록에 넣고, 보낸 이미지는 대화에 썸네일로 남긴다.MVP
5. 워크트리기준 브랜치(기본 develop)를 고르면 새 브랜치로 워크트리를 만든다.git fetch 후 git worktree add ../{repo}-{티켓} -b {브랜치} origin/{기준}. 브랜치명은 티켓 번호 + 요약으로 제안. 세션 종료 시 삭제 여부 확인.MVP
6. 서버 실행AI가 필요한 환경값을 찾아 보여주면, 사용자가 키·값·필수 여부를 고치거나 추가·삭제한 뒤 빈 포트로 서버를 띄운다. 값은 프로필별로 저장한다..env.example, application.yml, 코드 내 참조를 Claude가 분석. 프로젝트마다 프로필 여러 개(local, dev-db 등)를 두고 전환. 항목마다 출처(AI 추정, 프로필, 자동, 직접 추가) 표시. 한 줄 추가와 .env 붙여넣기 지원. 저장은 프로필 덮어쓰기, 새 프로필, 이번 세션만 중 선택. FE의 API 주소는 같은 세션 BE 포트로 자동 연결. DB는 공용이 기본이고, 세션 설정에서 접속 정보를 바꿀 수 있다.2단계
7. FE 미리보기헬스체크 통과 시 오른쪽 패널에 화면을 띄운다.iframe 기본, 쿠키 제약 대비 "새 창으로 열기" 제공. 계정 풀에서 세션마다 테스트 계정을 자동 배정해 세션 끊김 방지.2단계
8. BE 로그서버 stdout/stderr를 실시간으로 보여준다.spawn 스트림을 WebSocket으로 전달. 레벨 필터, 검색, 에러 줄을 Claude에게 보내는 버튼.2단계
9. 푸시와 PR템플릿을 채워 푸시와 함께 일반 PR을 바로 연다. 리뷰 단계는 없다..github/pull_request_template.md + diff + 대화 요약으로 본문 생성. 빌드·테스트 통과 시 git push -u → gh pr create --base {기준}.3단계
10. 영향 화면 확인수정이 여러 화면에 걸치면 영향받는 화면 목록을 만들고, 기준 브랜치와 작업 브랜치 화면을 찍어 전후를 비교한다.변경 파일에서 라우터 설정과 import 관계를 따라 경로를 찾고, 상세 경로 ID는 Claude가 테스트 데이터에서 고른다. Playwright로 배정 계정 로그인 후 촬영, 픽셀 비교로 바뀐 영역 표시. 기준 화면은 develop 공용 기준 서버에서 찍는다. 화면별로 의도한 변경 표시 또는 전후 이미지로 Claude에게 수정 요청.3단계
11. 리소스 정리PR을 만들면 서버를 끄고, PR이 머지되거나 닫히면 워크트리, 로컬 브랜치, 계정, 스크린샷을 정리 대기로 올려 한 번에 지운다.10분마다 gh pr view로 상태 확인. 미커밋 변경이 있는 워크트리는 보호되어 자동 삭제하지 않는다. 7일 미활동 세션은 알림만. 도구 시작 시 주인 없는 프로세스 종료, git worktree prune, 미연결 계정 반납. 원격 브랜치 삭제는 선택.3단계
12. 알림프롬프트 작업이 끝나거나 오류로 멈추면 알린다. 서버 실패, PR 완료·테스트 실패도 알릴 수 있다. 누르면 해당 세션이 열린다.SDK의 result 메시지를 받으면 오케스트레이터가 OS 알림(node-notifier)을 보내 탭을 닫아도 동작. 탭 제목 배지, 사이드바 "작업 완료" 표시. 보고 있는 세션은 생략, 기준 시간(기본 30초)보다 짧은 작업은 생략.MVP

핵심 흐름: 티켓 시작부터 PR까지

  1. 세션 만들기. 워크스페이스와 기준 브랜치를 고르고 티켓 번호를 입력한다.
  2. 워크트리 생성. BE/FE 각각 워크트리와 브랜치가 만들어지고 세션에 기록된다.
  3. 프롬프트로 개발. Claude가 워크트리 안에서 코드를 수정한다. 진행 상황이 스트림으로 보인다.
  4. 서버 실행. 고른 환경값 프로필을 적용하고, AI가 찾은 항목을 확인하고 고친다. 빠진 값은 직접 넣거나 .env로 붙여넣는다. BE와 FE가 각자 빈 포트로 뜨고, 계정 풀에서 테스트 계정이 배정된다.
  5. 확인. 미리보기 패널에서 화면을, 로그 패널에서 BE 로그를 본다. 문제가 있으면 로그나 화면 캡처를 Claude에게 넘긴다.
  6. 푸시와 PR 생성. 빌드와 테스트가 통과하면 템플릿대로 본문을 채워 푸시하고 PR을 연다. 링크가 세션에 남고 서버는 꺼진다.
  7. 정리. PR이 머지되면 정리 대기에 올라오고, 확인하면 워크트리와 브랜치, 계정을 정리한다.

데이터 모델

테이블주요 필드설명

workspacesid, name, project_ids[]함께 띄우는 BE/FE 묶음

env_profilesid, project_id, name, is_default프로젝트별 환경값 프로필 (local, dev-db 등)

환경값은 OS 키체인(keytar)에 키를 두고 값을 암호화해 저장한다. 비밀값은 UI에서 가려서 보여준다.

로드맵

phase-1 · 1~2주 · 구현 완료

워크트리 위에서 Claude와 대화

프로젝트 등록, 워크트리 생성, Agent SDK 세션, 프롬프트 창과 스트림 렌더링, 작업 완료 알림.

완료 기준 티켓 번호를 넣으면 워크트리가 생기고, 그 안에서 Claude가 코드를 고치는 과정이 화면에 보인다.

phase-2 · 2주 · 구현 완료

서버 실행과 확인

환경값 분석, 프로필 여러 개 관리와 편집, .env 붙여넣기, 포트 할당, 프로세스 관리, FE 미리보기, BE 로그 뷰어, 테스트 계정 풀, GitHub 인증 확인.

완료 기준 워크트리 3개를 동시에 띄워도 포트가 겹치지 않고, 각 화면과 로그를 탭으로 오갈 수 있다.

phase-3 · 1주

PR 자동화

템플릿 파싱, 본문 생성, PR 전 빌드·테스트 게이트, 푸시와 PR 생성, 영향 화면 목록과 전후 스크린샷 비교, 리소스 정리 화면과 자동 정리 규칙.

완료 기준 버튼 한 번으로 템플릿 항목이 채워진 PR이 develop 대상으로 열린다.

phase-4 · 이후

다듬기

세션 기록 검색, 에러 로그 기반 자동 수정 제안, 세션별 DB 설정 프리셋.

리스크와 대응

리스크영향대응
높음 좀비 프로세스도구가 죽으면 서버가 포트를 계속 잡고 있다.pid를 DB에 기록하고 시작 시 정리. 프로세스 그룹 단위로 종료.
높음 환경값 오판Claude가 필요한 값을 놓치거나 잘못 추정한다.AI 추정 항목을 따로 표시하고, 모든 항목을 사용자가 고치거나 지울 수 있다. 실행 실패 로그는 다시 분석에 넣는다.
중간 iframe 로그인SameSite 쿠키 때문에 미리보기에서 로그인이 안 될 수 있다.새 창 열기 기본 제공. 필요하면 로컬 리버스 프록시로 같은 출처 처리.
중간 의존성 설치 시간워크트리마다 node_modules 설치가 느리다.pnpm 사용 시 스토어 공유. Gradle은 공용 캐시 그대로 사용.
중간 잘못된 PR리뷰 단계가 없어 잘못된 변경이 바로 PR로 올라간다.PR 전에 빌드와 테스트를 자동 실행하고 실패하면 멈춘다. 만든 PR은 세션 화면에서 바로 닫을 수 있다.
중간 auto 모드 오작동Claude가 확인 없이 원치 않는 명령을 실행한다.작업 범위를 워크트리 디렉터리로 제한하고, 실행한 명령을 모두 세션 기록에 남긴다.
중간 공용 DB 충돌스키마를 바꾸는 티켓이 다른 세션의 DB를 깨뜨린다.세션 설정에서 별도 DB로 바꿀 수 있게 하고, 마이그레이션 파일이 diff에 있으면 경고한다.
중간 화면 비교 오탐데이터나 시간처럼 매번 바뀌는 영역이 차이로 잡힌다. 기준 서버가 오래되면 비교가 틀어진다.같은 계정·같은 데이터로 찍고, 날짜 같은 영역은 가림 규칙으로 제외. 기준 서버는 develop이 바뀔 때 자동 갱신.
낮음 계정 풀 고갈동시 세션이 계정 수보다 많아진다.세션 종료 시 계정을 반납하고, 남는 계정이 없으면 세션 생성 전에 알린다.
낮음 비밀값 노출환경값이 로그나 PR 본문에 섞인다.로그 출력과 PR 본문 생성 전에 저장된 비밀값을 마스킹.

결정 사항

형태: localhost 웹앱

데스크톱 패키징은 하지 않는다. 서버 정리는 오케스트레이터 종료 훅이 맡는다.

Claude 권한: auto 모드

파일 수정과 명령 실행을 확인 없이 진행한다. 실행 기록은 세션에 모두 남긴다.

테스트 계정: 도구가 계정 풀로 관리

세션 생성 시 자동 배정하고 종료 시 반납한다. 계정 등록 화면이 Phase 2에 들어간다.

PR: 리뷰 없이 일반 PR로 바로 생성

Draft를 쓰지 않는다. 대신 빌드·테스트 통과를 PR 생성 조건으로 둔다.

DB: 공용이 기본, 사용자가 세션별로 설정

세션 설정에서 DB 접속 정보를 덮어쓸 수 있다.

환경값: 프로필 여러 개, AI 분석 결과는 모두 편집 가능

키, 값, 필수 여부를 고치고 지울 수 있다. 직접 추가와 .env 붙여넣기를 지원한다.

프로젝트: 로컬 클론 폴더 기준

GitHub 레포 목록에서 고르지 않는다. GitHub는 푸시와 PR에만 쓴다.
