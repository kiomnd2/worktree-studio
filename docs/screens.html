상호작용

  • 누를 수 있는 요소는 높이 36~44px. 아이콘만 있는 버튼은 이름(aria-label)을 붙인다.
  • 되돌릴 수 없는 동작(워크트리 삭제, 프로젝트 등록 삭제)은 확인 창을 거친다.
  • 오류는 무엇이 잘못됐고 어떻게 고치는지 한 문장으로 적는다. 예: "브랜치 feature/DRMS-424가 이미 있습니다. 다른 이름을 쓰세요."
  • 빈 화면은 다음 할 일을 안내한다. 예: 세션이 없으면 "새 세션", "프로젝트 등록" 버튼.
  • 폭 1100px 미만에서는 오른쪽 패널을 숨기고, 760px 미만에서는 사이드바가 위로 쌓인다.

화면 흐름

  1. 설정(5)에서 로컬 폴더를 등록하고 워크스페이스를 만든다.
  2. 새 세션(2)에서 티켓과 기준 브랜치를 고른다.
  3. 빠진 환경값이 있으면 서버 실행 준비(3)를 거친다.
  4. 세션 작업 화면(1)에서 프롬프트로 개발하고 미리보기와 로그로 확인한다.
  5. 여러 화면에 영향이 있으면 전후 비교(6)로 확인한다.
  6. 푸시와 PR(4)으로 PR을 올린다.
  7. 머지되면 리소스 정리(7)에서 치운다.

1. 세션 작업 화면

Phase 2까지 구현
목적
티켓 하나의 작업을 처음부터 끝까지 진행하는 기본 화면. 대화, 미리보기, 로그를 창 전환 없이 본다.
들어오는 길
앱 첫 화면. 사이드바 세션 선택. OS 알림 클릭 시 ?session=ID로 바로 열림.

구성 요소

영역내용구현 상태
상단 바티켓, 요약, 브랜치, BE/FE 포트 상태, 배정 계정, 알림 종(개수), 서버 재시작, 푸시하고 PR 만들기티켓, 브랜치, 서버 포트 상태, 배정 계정 구현. 알림 종과 PR 버튼은 Phase 3
사이드바새 세션 버튼, 워크스페이스별 세션 목록(작업 중 / 작업 완료 · 새 결과 / 대기), 프로젝트와 설정, 리소스 정리(대기 개수)구현. 리소스 정리 링크는 Phase 3
대화 스트림사용자 메시지(첨부 썸네일 포함), Claude 텍스트(마크다운, 표), 도구 실행 카드(접힘, 결과 표시), 완료 줄(시간, 비용, 턴, 알림 여부)구현
프롬프트 입력첨부 칩(썸네일, 크기, 빼기), 입력창, 클립 버튼, 작업 위치, 보내기/중단구현
오른쪽 패널영향받는 화면 체크리스트, 미리보기(주소, 새로고침, 캡처해서 첨부, 새 창), BE 로그(레벨 필터, Claude에게 보내기)서버 실행·끄기·재시작, 미리보기(경로, 새로고침, 새 창), 로그(탭, 레벨 필터, 검색, Claude에게 보내기), 테스트 계정 보기·복사 구현. 영향 화면 체크리스트와 캡처해서 첨부는 Phase 3

동작과 규칙

  • Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 Enter는 무시
  • 이미지는 클립, 끌어다 놓기, 붙여넣기로 첨부. PNG/JPG/GIF/WEBP, 장당 5MB, 최대 10장
  • 작업 중에는 보내기 대신 중단 버튼
  • 보고 있는 세션의 "새 결과" 표시는 화면에 들어오면 자동으로 지움
  • 스크롤이 아래쪽 근처일 때만 새 메시지에 맞춰 자동 스크롤

2. 새 세션 만들기

Phase 1 구현
목적
티켓 단위로 워크트리와 브랜치를 한 번에 만든다.
들어오는 길
사이드바 "+ 새 세션", 빈 화면의 "새 세션" 버튼. 구현에서는 대화상자로 열림.

구성 요소

영역내용구현 상태
기본 정보워크스페이스, 티켓 번호, 작업 요약구현
브랜치프로젝트마다 기준 브랜치(develop 우선 정렬)와 새 브랜치명. 기본값 feature/{티켓}, 직접 수정 가능구현
테스트 계정계정 풀에서 자동 배정, 남은 계정 수구현 (생성 시 자동 배정, 안내 문구)
데이터베이스공용 개발 DB / 이 세션만 다른 DB환경값 화면의 "이번 세션에만 적용"으로 대신함
첫 프롬프트선택 입력. 넣으면 세션 생성 직후 실행구현
진행 안내fetch, 워크트리 생성, 환경값 복사, 서버 실행, Claude 세션 순서 안내대화상자 안내 문구로 대신함

동작과 규칙

  • 워크트리 경로는 클론 폴더 옆 {폴더}-{티켓 숫자}, 이미 있으면 -2, -3을 붙임
  • 같은 이름 브랜치가 있으면 오류로 멈춤
  • 여러 프로젝트 중 하나라도 실패하면 이미 만든 워크트리를 되돌림
  • origin이 없거나 오프라인이면 로컬 브랜치 기준으로 진행
  • Esc나 바깥 클릭으로 닫힘

3. 서버 실행 준비 (환경값)

Phase 2 구현
목적
AI가 찾은 환경값을 확인·수정하고, 프로필로 저장한 뒤 서버를 띄운다.
들어오는 길
세션 생성 후 빠진 값이 있을 때, 또는 상단 바 서버 재시작 전.

구성 요소

영역내용구현 상태
요약채워진 수, 입력 필요 수구현
출처 범례AI 추정, 프로필, 자동(포트·연결 주소), 직접 추가구현
레포별 표프로필 전환 버튼과 새 프로필. 행마다 키, 값, 찾은 곳(근거 위치), 필수, 출처, 삭제구현
직접 입력+ 변수 추가, .env 붙여넣기(KEY=VALUE, 기존 키는 값만 갱신)구현
하단저장 방식(프로필 덮어쓰기 / 새 프로필 / 이번 세션만), AI로 다시 분석, 서버 실행구현

동작과 규칙

  • 입력 필요 행은 주황 테두리로 강조
  • 비밀값은 password 입력과 마스킹
  • 포트는 빈 포트를 자동 배정, FE의 API 주소는 같은 세션 BE 포트로 연결
  • AI 추정 항목은 필수 해제나 삭제 가능
  • 프로필이 비어 있으면 워크트리를 정적으로 분석하고, 원본 클론 폴더의 .env 값을 가져와 미리 채움 (출처: 분석, 클론 .env)
  • "AI로 분석"은 Claude에게 읽기 도구만 주고 분석시킴. 1~2분 걸림
  • 서버 실행 시 필수 값이 비어 있으면 이 화면으로 돌아와 빠진 키를 알려 줌

4. 푸시와 PR 생성

Phase 3
목적
리뷰 단계 없이 검사를 통과하면 PR까지 바로 만든다.
들어오는 길
상단 바 "푸시하고 PR 만들기".

구성 요소

영역내용구현 상태
레포별 진행커밋, 빌드, 테스트, 푸시, PR 생성 단계와 소요 시간-
완료 후PR 열기, PR 닫기, 서버를 끄고 포트를 반납했다는 안내-
실패 안내테스트 실패 시 멈추고 로그를 Claude 세션에 넘길지 묻기-
PR 본문템플릿 기준 제목, 작업 내용, 테스트 표, 관련 PR, 체크리스트-

동작과 규칙

  • Draft가 아닌 일반 PR로 생성
  • 본문 생성 시 환경값과 계정 비밀번호를 자동으로 가림
  • BE와 FE PR은 서로를 관련 PR로 연결

5. 프로젝트와 계정 풀 (설정)

Phase 2까지 구현
목적
로컬 프로젝트, 워크스페이스, 테스트 계정, 알림을 관리한다.
들어오는 길
사이드바 아래 "프로젝트와 설정".

구성 요소

영역내용구현 상태
프로젝트 표로컬 폴더 경로, 현재 브랜치·워크트리 수·origin, 종류, 실행 명령({port} 자리에 포트), 포트 변수, BE 주소 변수, PR 전 검사, 헬스체크, 편집, 삭제구현
로컬 폴더 추가경로 입력, 폴더 분석 후 추가(git 저장소가 아니면 거부)구현. 찾아보기 버튼은 미구현
워크스페이스묶음 목록, 이름과 프로젝트 선택으로 만들기, 삭제구현
테스트 계정 풀계정, 비밀번호(가림), 상태(사용 중/대기), 사용 세션, 반납·편집구현 (편집 대신 삭제 후 다시 추가)
Claude와 알림권한 모드(기본 auto), 알릴 일, 알리는 방법, 보고 있을 때 생략, 최소 시간, 테스트 알림구현. 서버 예기치 않은 종료 알림 포함. PR·정리 알림은 Phase 3

동작과 규칙

  • 프로젝트 행은 바뀐 값이 있을 때만 저장 버튼이 보임
  • 열린 세션이 쓰는 프로젝트·워크스페이스는 삭제 불가
  • 등록 삭제는 폴더를 지우지 않음

6. 영향받는 화면 전후 비교

Phase 3
목적
수정이 여러 화면에 걸칠 때 빠짐없이 확인하고 의도치 않은 변경을 잡는다.
들어오는 길
세션 화면 체크리스트의 "전후 비교 보기".

구성 요소

영역내용구현 상태
상단기준(develop 공용 기준 서버)과 작업 서버, 촬영 계정·해상도, 보기 방식(나란히/겹쳐 보기/차이만), 다시 찍기-
화면 목록경로, 결과(차이 %, 같음, 찍기 실패), 영향 이유(직접 수정 / 어떤 파일을 통해), 화면 직접 추가-
비교 영역변경 전후 스크린샷, 번호 붙은 차이 박스, 차이 설명-
하단의도한 변경으로 표시, 전후 이미지로 Claude에게 수정 요청, 미리보기에서 열기, 확인 개수-

동작과 규칙

  • 변경 파일에서 라우터와 import를 따라 화면 경로를 찾음
  • 상세 경로 ID는 Claude가 테스트 데이터에서 고름
  • 날짜처럼 매번 바뀌는 영역은 가림 규칙으로 제외

7. 리소스 정리

Phase 3
목적
끝난 세션의 워크트리, 브랜치, 계정, 스크린샷을 안전하게 치운다.
들어오는 길
사이드바 "리소스 정리", PR 화면 안내 링크.

구성 요소

영역내용구현 상태
요약정리할 수 있는 세션 수와 확보 용량, 선택한 세션 정리-
세션 표PR 상태, 서버, 워크트리 수·용량·미커밋 여부, 계정, 상태(정리 대기/보호됨/머지 대기/작업 중)-
진행 순서서버 종료, 워크트리 삭제, 로컬 브랜치 삭제, 계정 반납, 스크린샷 삭제, 기록 보관. 원격 브랜치 삭제와 대화 기록 보관은 옵션-
자동 정리 규칙PR 생성 시 서버 끄기, 머지·닫힘 시 정리 대기, 확인 없이 정리, 7일 미활동 알림-
시작 때 발견한 것주인 없는 서버 프로세스 종료, 폴더 없는 워크트리 기록 정리-

동작과 규칙

  • 미커밋 변경이 있는 세션은 어떤 설정에서도 자동 삭제하지 않음
  • 작업 중·머지 대기 세션은 선택 불가
  • Phase 1에서는 세션 정보 패널의 "세션 닫기 / 닫고 워크트리 삭제"로 대신함
