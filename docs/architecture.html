Worktree Studio 구조와 Claude 하네스

저장소가 어떻게 나뉘어 있는지, 실행하면 어떤 프로세스가 뜨는지, 그리고 Claude를 어떤 설정과 도구, 승인 흐름으로 감싸 쓰는지 정리한다.

한눈에

  • npm 워크스페이스 모노레포. server(Node + Fastify, 약 12,000줄)와 web(React + Vite, 약 9,800줄), 그리고 워크스페이스 밖의 desktop(Electron 패키징)으로 나뉜다.
  • 서버 하나가 HTTP API(라우트 약 160개)와 WebSocket(/ws)을 열고, git·gh·개발 서버 프로세스·Claude Code를 직접 다룬다.
  • Claude는 @anthropic-ai/claude-agent-sdk의 query()로 부른다. 쓰임은 두 가지다. 사용자와 대화하는 대화 하네스(메인·추가·DB 대화)와, 화면 뒤에서 구조화된 결과만 받는 보조 호출 9종.
  • 모든 상태는 ~/.worktree-studio/studio.db(SQLite) 하나에 있다. 첨부, 스크린샷, 테스트 결과, 산출물 문서는 같은 폴더 아래에 파일로 둔다.

Claude 하네스

모든 Claude 호출은 Agent SDK의 query()를 쓰고, 끝나면 recordUsage로 사용량을 남긴다. 실행 파일은 WTS_CLAUDE_PATH가 있으면 그것, 없으면 SDK 기본값이다.

하네스언제작업 폴더도구권한 모드세션 유지
메인 대화세션의 기본 대화 (chatId 0)첫 워크트리, 나머지 워크트리와 산출물 폴더는 추가 디렉터리Claude Code 기본 도구 + studio + browser설정값(기본 auto), 계획 요청이면 planresume으로 이어감
추가 대화같은 세션에서 다른 일을 동시에같음같음, 단 set_tasks 금지같음대화마다 따로
DB 대화DB 연결 하나에 질의만같음 (읽기만)studio 일부. Edit Write NotebookEdit Bash와 요청형 도구 금지, browser 없음같음대화마다 따로
보조 호출 9종PR 문안, 화면 찾기, 테스트 등호출마다 다름Read Grep Glob만, 또는 없음, 또는 browser만dontAsk저장 안 함 (persistSession: false)

대화 하네스의 주요 옵션 (server/src/claude.ts runPrompt)

query({
  prompt: input(),                          // streaming input: 첨부 블록 + 본문 + <tool_context>
  options: {
    cwd: primary.path,
    additionalDirectories: [...다른 워크트리, docsDir(sessionId)],
    resume: chat.claude_session_id,
    model: chatModel(),                     // 설정의 defaultModel, 비면 Claude Code 기본
    permissionMode: opts.plan ? 'plan' : 설정값,
    planModeInstructions: PLAN_INSTRUCTIONS,  // 계획 요청일 때만
    canUseTool,                             // 아래 "권한과 승인"
    settingSources: ['user', 'project', 'local'],
    systemPrompt: { type: 'preset', preset: 'claude_code', append: buildSystemAppend(...) },
    strictMcpConfig: true,                  // 사용자 설정의 MCP·커넥터는 쓰지 않음
    mcpServers: { studio, browser },
    settings: { autoCompactWindow: 300_000, enabledPlugins: { 'bkit@bkit-marketplace': false } },
    allowedTools: [studio 도구 17개, 'mcp__browser'],
    disallowedTools: 대화 종류별,
  },
})

프롬프트 층

Claude가 받는 지시는 네 층으로 쌓인다. 시스템 프롬프트는 세션 처음에 고정되므로, 바뀌는 정보는 매 메시지에 붙인다.

언어: Studio가 Claude에게 보내는 지시문(시스템 규칙, 계획·보고서 지시, 도구 설명, <tool_context>, 보조 호출 프롬프트)은 영어로 쓴다. 시스템 규칙 맨 앞의 LANGUAGE_RULE과 보조 호출마다 넣은 출력 언어 규칙으로, 사람이 읽는 출력(대화 답변, 질문, 문서, 작업 목록, PR·커밋 문구, 테스트 케이스)은 한국어로 받는다. 도구가 Claude에게 돌려주는 결과 문구와 사용자에게 보이는 오류는 한국어 그대로다.

  1. 1. Claude Code 프리셋preset: 'claude_code'. 사용자·프로젝트·로컬 설정을 읽으므로 워크트리의 CLAUDE.md와 사용자 스킬도 적용된다.
  2. 2. Studio 규칙 (buildSystemAppend)워크트리 밖 수정 금지, 커밋·푸시·PR은 요청 시에만, 개발 서버는 직접 띄우지 않음, 긴 출력은 tail로, 환경값·계정·DB 쓰기는 도구로 요청, 정할 것은 AskUserQuestion으로, 산출물은 save_doc으로 저장(계획서·DB 변경 설계서는 Markdown, 화면설계서는 HTML), 작업 목록 갱신 규칙, 완료 보고서 순서(REPORT_INSTRUCTIONS). erd-vibe가 설정돼 있으면 사전 규칙(DICT_RULE)이 붙는다. 추가 대화와 DB 대화는 앞에 전용 규칙이 더해진다.
  3. 3. 계획 모드 지시 (PLAN_INSTRUCTIONS)계획 요청일 때만. 코드 읽기 → 계획서 HTML 저장(업무 흐름이면 인라인 SVG 플로우) → 화면설계서 → DB를 바꾸면 DB 변경 설계서(kind "db", 용어사전 확인 표 포함) → set_tasks로 작업 목록 → ExitPlanMode.
  4. 4. 메시지별 <tool_context> (runtimeContext)실행 중인 개발 서버 주소, 작업 목록, 이 세션의 산출물 문서 경로, 질의할 수 있는 DB 연결, 사전 상태, 배정된 테스트 계정. /compact 같은 슬래시 명령에는 붙이지 않는다.

권한과 승인

canUseTool은 권한 모드가 확인을 요구할 때만 불린다. 화면에 승인할 곳이 있는 도구만 통과시킨다.

도구처리
mcp__studio__*허용 승인이 필요한 도구는 도구 안에서 따로 승인을 받는다.
AskUserQuestion질문 카드 답을 받아 answers로 넘긴다. 답이 없으면 거절하고 "추측하지 말고 정리해 마치라"고 알린다.
ExitPlanMode계획 승인 카드 이번 실행에서 저장한 문서를 함께 보여 준다. 승인하면 설정의 권한 모드로 바꿔 이어 실행하고, 의견을 주면 문서를 다시 저장하게 한다.
그 밖거절 "승인 화면이 없어 쓸 수 없다"고 돌려준다.

승인 카드 종류 (approvals.ts)

Claude 실행은 사용자가 카드를 처리할 때까지 그 자리에서 기다린다. 실행이 끝나거나 중단되면 그 대화의 대기 카드는 취소된다.

kind누가 올리나승인하면
envrequest_env_values사용자가 고친 값이 환경값 프로필에 들어간다.
planExitPlanMode실행 모드로 바뀌고 첫 작업이 시작된다.
questionAskUserQuestion답이 Claude에게 넘어간다.
dbwritedb_query에 쓰기 SQL사용자가 확인한 SQL을 실행한다.
testdata화면 테스트 실행 중 데이터 부족데이터를 만들고 케이스를 다시 실행한다.

사전 등록·ERD 변경·예외·기준선 요청은 승인 카드가 아니라 dict_requests에 쌓이고, 용어 화면에서 승인한다. 도구는 기다리지 않고 바로 돌아온다.

browser MCP

@playwright/mcp를 stdio로 띄운다. --headless --browser chrome --isolated --ignore-https-errors --viewport-size 1440,900. 스크린샷은 워크트리가 아니라 ~/.worktree-studio/screens/{세션}/chat에 남겨 커밋에 섞이지 않게 한다. DB 대화에는 띄우지 않는다.

보조 호출

화면 뒤에서 한 번 돌고 끝나는 호출이다. 공통 설정은 permissionMode: 'dontAsk', settingSources: [](사용자 플러그인·훅을 불러오지 않음), persistSession: false, outputFormat: json_schema로 구조화된 결과만 받는다. 모델은 설정의 helperModels[용도] → defaultModel → Claude Code 기본 순서로 고른다(models.ts).

개발 하네스

명령하는 일
npm run devtsx watch 서버(4317)와 Vite 화면(5317)을 함께. 서버 파일을 고치면 서버가 다시 뜨면서 이 도구가 띄운 세션 서버도 꺼진다.
npm run typecheckserver, web 순서로 tsc --noEmit. 자동 테스트는 아직 없어서 이것이 기본 검증이다.
npm run build / npm start화면 빌드 후 서버 하나로 4317에서 실행.
npm run package:macdesktop/release/에 dmg·zip (arm64, ad-hoc 서명).

포트 관련 환경변수: WTS_PORT, WTS_API_PORT, PORT(세션 개발 서버로 떴을 때 +1), WTS_WEB_ONLY, WTS_HOST. 자세한 표는 루트 README.md.

알아 둘 점

  • 대화에서는 bkit 플러그인을 끈다. Bash 호출마다 훅 문구를 넣고 매 답변에 보고 표를 요구해서 대화가 길어진다. 보조 호출은 settingSources: []라 원래 불러오지 않는다(훅이 작업 폴더에 상태 파일을 만들면 커밋에 섞이기 때문).
  • strictMcpConfig: true로 사용자 설정의 MCP·커넥터를 막는다. 도구 목록이 바뀔 때마다 대화에 목록이 다시 들어가 토큰이 늘기 때문이다.
  • 자동 요약은 300,000토큰에서. compact_boundary 메시지를 받으면 대화에 "요약됨" 이벤트로 남긴다.
  • 대기열: 대화마다 한 번에 하나만 돈다. 실행 중에 보낸 프롬프트는 prompt_queue에 쌓이고, 중단하거나 오류로 끝나면 대기열이 멈춰 사용자가 보고 이어 간다.
  • 워크트리 제한은 프롬프트 수준이다. auto 모드에서 Claude가 워크트리 밖을 건드리는 것을 강제로 막지는 않으므로 도구 카드로 확인한다.
  • 원본 폴더 세션(in_place)은 다른 작업과 폴더를 같이 쓰므로, 브랜치를 바꾸거나 되돌리는 git 명령은 사용자에게 묻도록 지시한다.
  • Studio 세션의 계획서·DB 변경 설계서는 Markdown이 원본이다. Claude는 <tool_context>에 적힌 .md를 읽고, 사람은 micromark로 만든 .html을 본다(docs.ts renderMarkdown). 화면설계서는 배치를 그려야 해서 HTML이 원본이다. 이 저장소 자체의 플랜(docs/plans/*.md)과는 다른 것이다.
