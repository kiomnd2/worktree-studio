# 워크트리 개발 도구 플랜

> 개발 계획서 v0.4 · 작성 2026-10-13 · 갱신 2026-11-19
> 상태: Phase 1~3 구현 완료, Phase 4 미착수
> 원본: `docs/plan.html` (v0.3, Phase 2 시점)에서 옮김

**프롬프트 하나로 워크트리부터 PR까지 가는 로컬 개발 도구.**
지금 터미널에서 손으로 이어 붙이는 작업, 즉 워크트리 생성, 포트를 나눠 서버 띄우기, 화면 확인, PR 작성을 한 화면에서 처리한다.

## 1. 배경과 목표

현재는 Claude Code를 터미널에서 실행하고, 작업마다 워크트리 경로와 포트(예: 3423, 3424)를 머릿속으로 관리한다. 서버가 여러 개 떠 있으면 어느 브랜치가 어느 포트인지 헷갈리고, 같은 테스트 계정으로 두 곳에 로그인하면 세션이 끊긴다. PR 본문은 매번 템플릿을 보며 직접 채운다.

### 목표

- 티켓 하나당 세션 하나: 세션을 만들면 워크트리, 브랜치, 포트, 환경값이 함께 묶인다.
- 프롬프트 입력부터 화면 확인까지 창을 바꾸지 않는다.
- PR은 템플릿에 맞춰 초안이 자동으로 만들어지고, 사람은 검토만 한다.

### 성공 기준

- 새 티켓 시작부터 로컬에서 화면을 보기까지 1분 안에 끝난다.
- 동시에 3개 이상의 워크트리 서버가 포트 충돌 없이 돈다.
- PR 템플릿 항목이 빠짐없이 채워진 초안이 나온다.

## 2. 범위

### 하는 것

- 로컬 Claude Code 세션 연동 (Agent SDK)
- GitHub 연동 (gh CLI)
- 로컬 클론 폴더 기준 프로젝트 등록과 BE/FE/통합 자동 감지
- 프롬프트 입력창과 대화 스트림
- 기준 브랜치 선택 후 워크트리 생성
- 프로필별 환경값 관리(AI 분석 후 수정·추가), 빈 포트로 서버 실행
- FE 미리보기, BE 로그 뷰어
- 템플릿 기반 PR 생성
- 테스트 계정 풀 관리

### 하지 않는 것

- 원격 서버 배포, 클라우드 호스팅
- 팀 단위 멀티 유저, 권한 관리
- 코드 에디터 기능 (IDE를 대체하지 않음)
- CI 결과 연동, 리뷰 코멘트 자동 대응
- DB 마이그레이션 자동 실행

## 3. 아키텍처

로컬 프로세스를 직접 다뤄야 하므로 Node.js(TypeScript) 오케스트레이터가 중심에 있고, 브라우저 UI는 WebSocket으로 상태를 받는다. `localhost` 웹앱으로 만든다. 도구를 끌 때 띄워 둔 서버는 오케스트레이터의 종료 훅에서 함께 정리한다.

```
웹 UI (React)  ── 프롬프트, 미리보기, 로그
     │ WebSocket / HTTP
     ▼
오케스트레이터 (Node)  ── 세션 상태, WebSocket, SQLite
     ├── Claude 세션   Agent SDK          server/src/claude.ts
     ├── 워크트리      git worktree       server/src/git.ts, sessions.ts
     ├── 서버 러너     포트, env, 로그     server/src/runner.ts, ports.ts, envstore.ts
     └── GitHub        gh CLI, PR         server/src/github.ts, pr.ts
```

네 모듈은 서로 직접 호출하지 않고 오케스트레이터를 통해서만 상태를 주고받는다.

### 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| UI | React + Vite, Tailwind | 스트리밍 메시지와 탭 UI를 빠르게 만들 수 있다. |
| 서버 | Node.js + Fastify, ws | Agent SDK가 TypeScript 기준이고 child_process 제어가 쉽다. |
| Claude | `@anthropic-ai/claude-agent-sdk` | 터미널 출력 파싱 없이 메시지 타입별로 스트림을 받는다. |
| Git / GitHub | git CLI, gh CLI | 사용자의 기존 인증을 그대로 쓴다. 토큰 저장이 필요 없다. |
| 저장소 | SQLite (better-sqlite3) | 로컬 단일 사용자에 충분하고 백업이 파일 하나다. |
| 포트 | get-port | 사용 중이지 않은 포트를 안전하게 찾는다. |

### 구현 결과 (계획과 달라진 점)

- **#10 영향 화면 확인**: 자동 촬영·픽셀 비교는 넣지 않았다. 대신 두 가지로 나눴다.
  - 영향 화면 체크리스트: Claude가 찾은 경로를 누르면 미리보기에서 열리고 사람이 직접 보고 확인 표시. 미리보기 화면을 찍어 프롬프트에 첨부하고 펜·네모·화살표로 표시할 수 있다.
  - 화면 테스트: Claude가 테스트 케이스(역할, 시작 화면, 단계, 기대 결과)를 만들고, Playwright MCP로 Chrome을 열어 단계를 따라가며 통과·실패·확인 불가를 판정한다.
- **#9 PR**: BE·FE PR이 서로를 관련 PR로 연결하고, 모든 레포의 PR 전 검사가 통과한 뒤에만 푸시한다. erd-vibe 연동 이후 "용어 검사" 단계가 추가됐다.
- 계획에 없던 추가 기능: 한 세션에 여러 대화, 머지 충돌 확인·해결, Jira 티켓 연동(없이도 세션 생성 가능), 사용량 보고서, macOS 앱 패키징, 원본 폴더에서 바로 작업하는 세션, 로컬 실행 환경(DB·도커), 쿼리 감시([query-monitor.md](query-monitor.md)), erd-vibe 사전 연동.

## 5. 핵심 흐름: 티켓 시작부터 PR까지

1. **세션 만들기**: 워크스페이스와 기준 브랜치를 고르고 티켓 번호를 입력한다.
2. **워크트리 생성**: BE/FE 각각 워크트리와 브랜치가 만들어지고 세션에 기록된다.
3. **프롬프트로 개발**: Claude가 워크트리 안에서 코드를 수정한다. 진행 상황이 스트림으로 보인다.
4. **서버 실행**: 환경값 프로필을 적용하고 AI가 찾은 항목을 확인·수정한다. 빠진 값은 직접 넣거나 .env로 붙여넣는다. BE와 FE가 각자 빈 포트로 뜨고 테스트 계정이 배정된다.
5. **확인**: 미리보기 패널에서 화면을, 로그 패널에서 BE 로그를 본다. 문제가 있으면 로그나 화면 캡처를 Claude에게 넘긴다.
6. **푸시와 PR 생성**: 빌드와 테스트가 통과하면 템플릿대로 본문을 채워 푸시하고 PR을 연다. 링크가 세션에 남고 서버는 꺼진다.
7. **정리**: PR이 머지되면 정리 대기에 올라오고, 확인하면 워크트리와 브랜치, 계정을 정리한다.

## 6. 데이터 모델

스키마 원본은 `server/src/db.ts`. 아래는 계획 시점의 주요 테이블이다.

| 테이블 | 주요 필드 | 설명 |
| --- | --- | --- |
| `projects` | id, name, local_path, kind(be/fe/full), start_cmd, check_cmd, health_path | 로컬 클론 폴더 하나. 브랜치와 원격 주소는 저장하지 않고 git에서 읽음 |
| `workspaces` | id, name, project_ids[] | 함께 띄우는 BE/FE 묶음 |
| `sessions` | id, workspace_id, ticket, base_branch, claude_session_id, account_id, env_profile_ids, db_override, status | 티켓 하나에 대응하는 작업 단위 |
| `worktrees` | id, session_id, project_id, path, branch | 세션이 만든 워크트리 |
| `servers` | id, worktree_id, port, pid, status, started_at | 실행 중인 서버 프로세스 |
| `env_profiles` | id, project_id, name, is_default | 프로젝트별 환경값 프로필 |
| `env_vars` | id, profile_id, key, value(암호화), required, source(ai/profile/auto/manual), found_in | 프로필에 속한 변수 한 줄 |
| `test_accounts` | id, project_id, email, password(암호화), session_id(배정), released_at | 테스트 계정 풀 |
| `screen_checks` | id, session_id, route, reason, before_asset, after_asset, diff_ratio, status(changed/same/failed/accepted) | 영향받는 화면 하나의 비교 결과 |
| `pull_requests` | id, session_id, number, url, state | 생성한 PR 기록 |

비밀값 저장: 계획은 OS 키체인(keytar)이었으나, 구현은 `~/.worktree-studio/secret.key`로 암호화해 DB에 저장한다(`server/src/secret.ts`). 비밀값은 UI에서 가려서 보여준다.

| Phase 2: 서버 실행과 확인 | 2주 | 환경값 분석, 프로필 관리·편집, .env 붙여넣기, 포트 할당, 프로세스 관리, FE 미리보기, BE 로그 뷰어, 테스트 계정 풀, GitHub 인증 확인 | 워크트리 3개를 동시에 띄워도 포트가 겹치지 않고, 각 화면과 로그를 탭으로 오갈 수 있다. | ✅ |

| Phase 4: 다듬기 | 이후 | 세션 기록 검색, 에러 로그 기반 수정 제안, 세션별 DB 설정 프리셋 | 미정 | ⬜ |

Phase 4의 "에러 로그 기반 수정 제안"은 자동 실행이 아니라 사람이 승인하는 형태로만 한다(자가 수정 기능은 품질 문제로 제거된 이력이 있음).

## 9. 결정 사항

- **형태: localhost 웹앱** — 서버 정리는 오케스트레이터 종료 훅이 맡는다. (이후 macOS 앱 패키징이 추가됐지만, 앱도 같은 로컬 서버에 창을 붙이는 방식이다.)
- **Claude 권한: auto 모드** — 파일 수정과 명령 실행을 확인 없이 진행한다. 실행 기록은 세션에 모두 남긴다. auto를 쓸 수 없는 환경은 `acceptEdits`로 바꾼다.
- **테스트 계정: 도구가 계정 풀로 관리** — 세션 생성 시 자동 배정하고 종료 시 반납한다.
- **PR: 리뷰 없이 일반 PR로 바로 생성** — Draft를 쓰지 않는다. 대신 빌드·테스트 통과를 PR 생성 조건으로 둔다.
- **DB: 공용이 기본, 사용자가 세션별로 설정** — 세션 설정에서 DB 접속 정보를 덮어쓸 수 있다.
- **환경값: 프로필 여러 개, AI 분석 결과는 모두 편집 가능** — 키, 값, 필수 여부를 고치고 지울 수 있다. 직접 추가와 .env 붙여넣기를 지원한다.
- **프로젝트: 로컬 클론 폴더 기준** — GitHub 레포 목록에서 고르지 않는다. GitHub는 푸시와 PR에만 쓴다.
- **영향 화면: 자동 비교 대신 사람 확인 + 화면 테스트** — 픽셀 비교는 오탐과 기준 서버 관리 부담이 커서 넣지 않았다.
