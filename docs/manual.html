사용 설명서 · 2026-10-14 기준

Worktree Studio 사용 설명서

Jira 티켓 하나에 git 워크트리 하나를 만들고, 그 안에서 Claude Code와 대화하며 개발합니다. 서버 실행, 미리보기, 화면 테스트, PR까지 한 화면에서 이어집니다.

시작하기

준비물

  • Node.js 20 이상, git
  • Claude Code 로그인: 터미널에서 claude를 실행해 /login을 한 번 해 둡니다.
  • GitHub CLI 로그인: gh auth login. PR 만들기와 PR 상태 확인에 씁니다.
  • 화면 테스트를 쓰려면 Chrome이 설치되어 있어야 합니다.

실행

npm install
npm run dev     # 서버 4317, 화면 5317 → http://localhost:5317

npm run build && npm start   # 서버 하나로 실행 → http://localhost:4317

처음 설정

왼쪽 아래 설정에서 한 번만 해 두면 됩니다. 설정은 워크스페이스·프로젝트, Jira, 테스트 계정, Claude와 알림 탭으로 나뉩니다.

  1. 워크스페이스 만들기. 새 워크스페이스에 이름(예: RE100)을 넣어 만듭니다. 워크스페이스마다 Jira 프로젝트 키(예: KERE)를 넣어 두면 세션을 만들 때 티켓을 고르거나 바로 만들 수 있습니다.
  2. 프로젝트 추가. 워크스페이스 카드 아래 칸에 로컬에 클론한 폴더 경로를 넣고 폴더 분석 후 추가를 누릅니다. BE·FE 종류, 실행 명령, 설치 명령, 헬스체크 경로가 채워집니다. 포트를 인자로 받는 FE는 실행 명령에 {port}를 넣고, Spring은 포트 변수 SERVER_PORT로 받습니다. 개발 서버가 HTTPS로 뜨면 접속 주소에 https://localhost:{port}를, 인증서의 도메인으로 열어야 하면 https://local.example.com:{port}처럼 넣습니다. 미리보기·헬스체크·화면 캡처·화면 테스트가 이 주소를 쓰고, 로컬 개발 인증서(자체 서명 포함)는 그대로 받아들입니다.
  3. 프로젝트 정리. 프로젝트는 한 줄 요약으로 보이고 설정으로 자세한 설정을 엽니다. 위아래 버튼으로 순서를 바꾸며 맨 위 프로젝트가 Claude의 작업 위치가 됩니다. 다시 분석은 Claude가 저장소를 읽고 로그인 없이 바로 뜨는 실행 방법을 제안합니다. 이미 등록한 프로젝트는 등록된 프로젝트 넣기로 다른 워크스페이스에도 넣을 수 있습니다.
  4. Jira 로그인. Jira 영역에서 Jira로 로그인을 누르고 Atlassian 화면에서 허용합니다. API 키나 앱 등록은 필요 없습니다. 사이트가 여러 개면 쓸 사이트를 고릅니다.
  5. 테스트 계정 풀. 화면 확인과 화면 테스트에 쓸 계정을 넣습니다. 메모에 역할(예: 관리자, 수요기업)을 적어 두면 Claude가 역할에 맞는 계정을 고르는 데 씁니다. 워크스페이스를 지정하면 그 워크스페이스 세션에서만 씁니다.

테스트 계정의 아이디와 비밀번호는 화면 확인을 위해 Claude에게 전달됩니다. 운영 계정은 넣지 마세요.

새 세션 만들기

+ 새 세션은 두 단계입니다.

① 티켓

  • 워크스페이스를 고르면 나에게 배정된 진행 중 티켓이 나옵니다. 키(KERE-368), 번호만(368), 제목 일부로 찾을 수 있습니다.
  • 새로 만들기: "하려는 일"을 적고 제목·내용 제안 받기를 누르면 Claude가 코드와 최근 티켓 형식을 보고 제목·유형·설명을 씁니다. 고친 뒤 티켓 만들고 다음을 누르면 Jira에 만들어지고 나에게 배정됩니다. 제안 없이 직접 쓰기도 됩니다.
  • 프로젝트가 필수로 요구하는 칸(예: 스프린트)은 유형을 고르면 나타납니다. 스프린트는 진행 중인 스프린트가 기본으로 골라져 있습니다.
  • Jira에 로그인하지 않았거나 워크스페이스에 Jira 키가 없으면 티켓 번호를 직접 넣습니다.

② 세션 설정

  • 프로젝트마다 기준 브랜치와 새 브랜치(기본 feature/티켓키)를 확인합니다.
  • 첫 프롬프트를 적어 두면 세션을 만들자마자 Claude가 시작합니다. ①에서 적은 "하려는 일"이 미리 들어갑니다.
  • 세션 만들기를 누르면 클론 옆에 프로젝트-티켓번호 폴더로 워크트리가 생깁니다. 원본 클론 폴더는 건드리지 않습니다.

Claude와 작업하기

  • 이미지·문서 첨부: 클립 버튼, 끌어다 놓기, 붙여넣기. 이미지(PNG·JPG·GIF·WEBP, 5MB), PDF(20MB), 텍스트 문서(md·html·txt·json·csv·yaml·코드 파일 등, 1MB)를 붙일 수 있고 Claude가 내용을 읽습니다. 첨부한 이미지의 ✏️를 누르면 펜·네모·화살표·글자로 표시해서 보낼 수 있습니다.
  • 대기열: Claude가 작업 중일 때 보내면 차례로 실행합니다. 중단하거나 오류로 끝나면 대기열이 멈추고, 이어서 실행을 눌러야 다음 것이 돕니다.
  • 추가 대화: 대화 위쪽의 + 새 대화로 같은 워크트리에서 Claude를 하나 더 돌립니다. 메인 대화가 작업 중이어도 바로 시작하고, 대화마다 따로 이어집니다. 로그를 보다 생긴 작은 수정처럼 메인 작업과 겹치지 않는 일에 쓰세요(같은 파일을 동시에 고치면 서로 덮어쓸 수 있습니다). 작업 목록은 메인 대화만 바꿉니다. 대화를 닫아도 고친 코드는 워크트리에 남습니다. 로그, 변경 파일, 문서, 화면 테스트, 미리보기 캡처, PR 검사 실패에서 넘기는 내용은 메인 대화가 아니라 새 대화 탭에 들어갑니다. 새 대화 탭이 이미 열려 있으면 거기에 더하고, 보내기는 직접 누릅니다.
  • 중단: 작업 중에 중단을 누르면 멈춥니다. 다음 프롬프트는 앞 대화를 이어서 받습니다.
  • 환경값 요청: Claude가 서버 실행에 필요한 값을 찾으면 승인 카드로 요청합니다. 값을 확인·수정해 "이번 세션에만" 또는 "프로필에 저장"으로 승인합니다. Claude는 .env 파일을 직접 만들지 않습니다.
  • 테스트 계정: 세션은 워크스페이스 계정과 공용 계정을 모두 쓰고, 다른 세션과 같이 씁니다. Claude는 메모(역할)를 보고 맞는 계정을 고릅니다. 맞는 역할 계정이 없으면 설정의 테스트 계정 풀에 추가해 달라고 합니다.
  • 다음 작업 진행: 작업 목록에 남은 항목이 있는데 Claude가 멈춰 있으면 목록 오른쪽에 다음 작업 진행이 나옵니다. 누르면 다음 항목 하나만 진행하고 멈춥니다. 중단돼 하는 중으로 남은 항목이 있으면 이어서 진행으로 바뀝니다. 대기열에 프롬프트가 있으면 나오지 않습니다.
  • Claude는 매 메시지마다 실행 중인 서버 주소, 쓸 수 있는 테스트 계정, 작업 목록, 이 세션의 산출물 목록을 받습니다.

권한은 설정의 권한 모드를 따릅니다. Claude가 커밋·푸시·서버 실행은 하지 않도록 안내받지만 강제는 아니므로, auto 모드에서는 도구 카드로 실행한 명령을 확인하세요.

계획 먼저

입력창 아래 계획 먼저를 켜고 보내면(버튼이 계획 세우기로 바뀝니다) Claude가 코드를 고치기 전에 계획을 세웁니다. 켜 둔 상태는 세션마다 기억합니다.

  1. Claude가 코드를 읽고 계획서를 만듭니다. 목표, 바꿀 파일과 이유, 단계, API·데이터 변경, 영향 범위, 테스트 방법, 확인할 것이 들어갑니다.
  2. 화면이 생기거나 바뀌면 화면마다 화면설계서를 만듭니다. 실제 배치를 본뜬 와이어프레임에 번호를 달고, 번호별 설명 표(항목, 동작, 검증 규칙, 데이터 출처)와 빈 목록·오류·권한별 상태를 함께 그립니다.
  3. 승인 카드에서 문서를 열어 보고 고릅니다.
    • 승인하고 실행: 바로 구현을 시작합니다.
    • 고쳐 달라고 하기: 적은 의견대로 문서를 고쳐 새 판으로 저장하고 다시 묻습니다.
    • 실행 안 함: 아무것도 고치지 않고 끝냅니다.

계획 모드가 아니어도 "화면설계서 만들어줘"처럼 요청하면 문서로 저장합니다.

서버·미리보기·로그

환경값

  • 서버 영역의 환경값에서 프로젝트별 값을 봅니다. 처음 열면 워크트리를 분석해 필요한 키를 채우고, 원본 클론 폴더의 .env 값을 가져옵니다.
  • 프로필(local, mock 등)을 여러 개 두고 세션마다 고릅니다. 저장은 지금 프로필에 덮어쓰기, 새 프로필로 저장, 이번 세션에만 적용 중에서 고릅니다.
  • 필수 값이 비어 있으면 서버를 띄우지 않고 빠진 키를 알려 줍니다.

서버 실행

  • 모두 실행 또는 프로젝트별 실행. 실행 전에 나갈 명령을 보여 주고, 빈 포트를 자동 배정합니다(BE 8081~, FE 3401~). FE의 BE 주소 변수는 같은 세션 BE 포트로 연결됩니다.
  • 새 워크트리는 처음 실행할 때 설치 명령(npm ci, uv sync 등)을 먼저 돌립니다.
  • 헬스체크가 통과하면 "실행 중"이 됩니다. 멈추거나 응답이 없으면 오류 요약이 뜨고 로그를 Claude에게 넘기기로 원인 찾기를 맡길 수 있습니다. 고칠지는 사용자가 정합니다.
  • Spring처럼 핫 리로드가 안 되는 서버는 코드를 바꾼 뒤 재시작합니다.

미리보기

  • FE가 실행 중이면 패널에 화면이 나옵니다. 경로 이동, 새로고침, 새 창, 크게 보기, 화면 맞춤이 있습니다.
  • 새 대화로 보내기: 지금 화면을 찍어 새 대화 탭에 첨부하고 경로를 입력창에 넣습니다.
  • 탭: +로 미리보기 탭을 더 열고 ×로 닫습니다. 탭마다 페이지가 따로 유지되고, 주소 칸에는 경로(/login)나 전체 주소(https://localhost:8081/...)를 넣을 수 있습니다. 화면 찍기·새 창은 지금 탭 기준입니다.
  • 앱에서: 미리보기 페이지가 연 팝업은 앱 안 작은 창으로 열려 원래 페이지와 이어집니다(인증서 팝업이 결과를 원래 페이지로 돌려주고 닫히는 흐름이 그대로 동작). 원래 페이지와 연결하지 않는 팝업(noopener)은 새 미리보기 탭으로 엽니다. 이 PC의 로컬 서버(목업 인증 서버 등)가 프레임을 막아도(X-Frame-Options) 미리보기 안에서 보입니다.
  • 브라우저에서: 다른 서버로 넘어가거나 팝업이 뜨면 "연결을 거부했습니다"로 막힐 수 있습니다. 그 탭은 새 창으로 여세요. 로그인 쿠키가 안 붙을 때도 새 창으로 엽니다.

로그

프로젝트별 탭, WARN 이상 필터, 검색. 오류 줄의 새 대화로 보내기는 앞뒤 줄과 함께 새 대화 탭의 입력창에 넣습니다. 비밀값은 가려집니다.

변경 확인

오른쪽 패널 맨 위 변경 파일 ▾에서 봅니다.

  • 변경 파일: 프로젝트별 바뀐 파일 수와 줄 수. 비교 보기에서 파일별 diff를 나란히 또는 한 줄로 보고, "기준 브랜치와" / "커밋 안 한 것만"을 고릅니다.
  • 영향받는 화면: 영향 화면 찾기를 누르면 Claude가 바뀐 코드에서 실제로 달라지는 화면 경로를 고릅니다. 경로를 누르면 미리보기에서 열리고, 직접 보고 확인 표시를 합니다. 경로를 직접 추가할 수도 있습니다.

화면 테스트

오른쪽 패널 화면 테스트 ▾에서 요약과 이 세션의 테스트 계정을 함께 보고, 테스트 만들기 / 테스트 보기로 테스트 화면에 들어갑니다.

  1. 테스트 케이스 만들기: Claude가 바뀐 내용과 대화를 보고 케이스(역할, 시작 화면, 단계, 기대 결과)를 만듭니다. 고치기·삭제·직접 추가가 됩니다.
  2. 테스트에 쓸 계정: 케이스에 필요한 역할마다 계정을 고릅니다. 고르기 전에는 그 역할의 케이스를 실행하지 않습니다.
  3. 전체 실행 또는 이것만 실행: Claude가 Chrome을 열어 단계를 따라가며 화면을 찍고 통과·실패·확인 불가를 판정합니다. 케이스 하나에 30초~2분쯤 걸립니다.

케이스가 하나 끝날 때마다 오른쪽 아래에 결과 알림이 뜹니다. 통과는 잠깐 보였다 사라지고, 실패·확인 불가·오류는 닫을 때까지 남습니다. 누르면 테스트 화면으로 갑니다. 실패·오류는 OS 알림도 보냅니다(설정의 오류 알림을 따르고, 보고 있는 세션이면 화면 알림만). 화면 테스트 ▾ 메뉴에는 실행 중이면 진행(예: 실행 2/5), 끝나면 실패 수나 통과 수가 표시됩니다.

실행이 막히는 경우

아래 중 하나라도 해당하면 실행 버튼이 꺼지고, 화면 위쪽 "아직 실행할 수 없습니다"에 이유가 나옵니다. 버튼에 마우스를 올려도 이유가 보입니다.

  • 세션의 서버 중 하나라도 실행 중이 아님 (BE 포함. 시작 중, 응답 없음, 멈춤도 해당)
  • FE 프로젝트가 없거나 실행 명령이 없음
  • Claude가 작업 중 (코드가 바뀌는 중)
  • 케이스를 만드는 중이거나 케이스가 없음
  • 역할별 계정을 확인하지 않음

실행이 끝날 때마다 스크린샷이 들어간 테스트 결과서가 산출물로 저장됩니다.

산출물과 보관함

산출물만들어지는 때
계획서"계획 먼저"로 보냈을 때, 또는 요청했을 때
화면설계서계획에 화면 변경이 있을 때, 또는 요청했을 때 (화면마다 하나)
테스트 결과서화면 테스트를 실행할 때마다 (스크린샷 포함)
  • 같은 문서를 다시 저장하면 새 판이 되고 예전 판은 남습니다. 문서 화면에서 판을 골라 봅니다.
  • 프롬프트에 언급: 입력창에 문서 경로가 들어가 Claude가 그 문서를 읽고 따릅니다.
  • 세션 안에서는 오른쪽 패널 산출물 ▾, 모든 세션은 왼쪽 아래 산출물 보관함에서 봅니다.
  • 보관함은 닫힌 세션까지 워크스페이스별로 모아 보여 줍니다. 티켓, 제목, 브랜치, 문서 이름으로 찾고, PR 링크도 같이 나옵니다.
  • 폴더 열기로 Finder에서 열 수 있습니다. 폴더마다 index.html(목록)과 meta.json(티켓, 브랜치, PR)이 있어 도구 없이도 읽을 수 있습니다.

산출물은 저장소가 아니라 데이터 폴더에 있어서 커밋·PR에 섞이지 않습니다. 세션을 닫거나 리소스 정리를 해도 지우지 않습니다.

푸시하고 PR 만들기

  1. 상단 바 푸시하고 PR 만들기를 누르면 레포별로 바뀐 파일과 커밋을 모읍니다. Claude가 PR 템플릿과 최근 머지된 PR(내 것 먼저) 형식대로 제목·본문을 쓰고, 레포의 커밋 템플릿대로 커밋 메시지를 씁니다. 보내기 전에 고칠 수 있습니다.
  2. 레포마다 상태가 나옵니다.
    • 새 PR: 새로 만듭니다.
    • 열린 PR 있음: 푸시만 합니다. PR 제목·본문도 새로 쓴 것으로 바꾸기를 켜면 본문도 바꿉니다.
    • 보낼 것 없음: 이미 PR로 보낸 작업이라 다시 올리지 않습니다.
  3. 검사하고 PR 만들기: 커밋 → PR 전 검사 → 푸시 → PR 생성. 모든 레포의 검사가 통과한 뒤에 푸시해서 한쪽만 올라가지 않습니다. 검사가 실패하면 멈추고, 출력을 로그를 새 대화로 보내기로 Claude에게 넘기거나 검사 실패 무시하고 진행을 고를 수 있습니다.

BE·FE PR은 본문 끝에 서로를 연결합니다. 비밀값과 계정 비밀번호는 본문에서 가립니다.

세션 닫기와 정리

  • 오른쪽 패널 세션 ▾: 워크트리 경로와 브랜치를 보고 세션 닫기(서버 끄고, 폴더는 남김) 또는 닫고 워크트리 삭제(커밋 안 한 변경도 지움)를 고릅니다.
  • 왼쪽 아래 리소스 정리: 세션별 PR 상태, 서버, 워크트리 용량과 미커밋 여부를 보고 정리합니다. 서버 종료 → 워크트리 삭제 → 로컬 브랜치 삭제 → (원격 브랜치 삭제) → 스크린샷 삭제 순서입니다. 미커밋 변경이 있으면 자동으로 지우지 않습니다.
  • PR이 머지·닫히면 알려 줍니다. 설정에서 켜면 확인 없이 정리합니다.

리소스 정리는 화면 테스트의 원본 스크린샷을 지우지만, 테스트 결과서와 계획서·화면설계서는 산출물 보관함에 그대로 남습니다.
